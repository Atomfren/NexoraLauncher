## 1. Критические уязвимости

### 1.1 Безопасность: Открытый CORS (Backend)
**Файл:** `backend/main.py:52-58`
```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],  # ❌ ОПАСНО
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```
**Проблема:** Разрешены все источники (`*`) с `allow_credentials=True`. Это позволяет любому сайту отправлять запросы к API от имени авторизованного пользователя.

**Риск:** XSS-атаки через CORS, кража сессий, несанкционированный доступ к данным.

**Рекомендация:** Указать конкретные домены:
```python
allow_origins=["http://localhost:3000", "https://yourdomain.com"]
```

---

### 1.2 Безопасность: Хранение токенов в открытом виде
**Файл:** `backend/core/auth.py:14-23`
```python
@dataclass
class UserProfile:
    access_token: str = ""  # ❌ Токен хранится в plaintext
    refresh_token: str = ""  # ❌ В JSON файле
```
**Проблема:** Токены Microsoft OAuth хранятся в `profile.json` в открытом виде. Файл доступен любому процессу на системе.

**Риск:** Если злоумышленник получит доступ к файлу, он может захватить аккаунт Microsoft пользователя.

**Рекомендация:** Использовать Windows DPAPI (для Windows) или шифрование AES-256 с ключом, сгенерированным из пароля/хеша системы.

---

### 1.3 Безопасность: `asyncio.run()` в потоках (PyQt)
**Файл:** `frontend/pages/instances_page.py:29`, `home_page.py:20-21`, `settings_page.py:25`, и др.
```python
def run(self):
    result = asyncio.run(self.api.list())  # ❌ Создаёт новый event loop
```
**Проблема:** Каждый `asyncio.run()` создаёт новый event loop. Это создаёт накладные расходы и может привести к утечкам ресурсов при частых вызовах.

**Риск:** Утечки памяти, непредсказуемое поведение при вложенных вызовах async кода.

**Рекомендация:** Использовать `QNetworkAccessManager` (родной HTTP клиент PyQt) или создать единственный event loop на время работы worker.

---

### 1.4 Безопасность: Информация в ошибках
**Файл:** `backend/api/v1/auth.py:65`, `backend/api/v1/instances.py:78`, и др.
```python
raise HTTPException(status_code=500, detail=f"Login failed: {e}")  # ❌
```
**Проблема:** В продакшене в ответе клиенту возвращается полное сообщение об ошибке, которое может содержать пути к файлам, названия таблиц БД, внутренние детали.

**Риск:** Информационное раскрытие, помогающее злоумышленникам спланировать атаку.

**Рекомендация:** В продакшене возвращать только `detail="Internal server error"`, полные логи — в server-side лог.

## 2. Архитектурные проблемы

### 2.1 Избыточная слоистая архитектура
**Проблема:** Проект имеет 4 уровня: Frontend → Backend API → Core → Services. Для десктопного приложения это чрезмерно:
- Frontend (PyQt6) → HTTP → Backend (FastAPI) → Core → Services

**Проблема:** Для локального десктопного приложения, где frontend и backend работают на одной машине, HTTP-коммуникация избыточна.

**Риск:** 
- Увеличенная задержка (overhead HTTP)
- Сложность отладки
- Необходимость управления двумя процессами
- Сложность разработки и тестирования

**Рекомендация:** Рассмотреть прямой вызов функций из core-модулей в frontend. Оставить API только если планируется мобильное приложение или веб-интерфейс.

---

### 2.2 Отсутствие единого состояния приложения
**Проблема:** Нет централизованного менеджера состояния (State Management). Каждое окно/страница создаёт свой `APIClient`:
```python
# instances_page.py
self.api_client = APIClient()
self.instances_api = InstancesAPI(self.api_client)
self.minecraft_api = MinecraftAPI(self.api_client)

# settings_page.py
self.api_client = APIClient()  # ❌ Новый клиент
self.settings_api = SettingsAPI(self.api_client)
```
**Риск:** Каждый компонент создаёт свои сессии, нет единого состояния, сложность синхронизации данных между страницами.

**Рекомендация:** Внедрить паттерн Singleton или Dependency Injection для API клиентов и общих сервисов.

---

### 2.3 Отсутствие обработки жизненного цикла процессов Minecraft
**Файл:** `backend/api/v1/minecraft.py:15`
```python
_processes: Dict[int, subprocess.Popen] = {}  # ❌ Никогда не очищается
```
**Проблема:** Запущенные процессы хранятся в словаре и никогда не удаляются.

**Риск:** Утечка памяти, словарь будет расти бесконечно при каждом запуске Minecraft.

**Рекомендация:**
- Удалять процесс из словаря после завершения (`process.poll() is not None`)
- Использовать `asyncio.create_subprocess_exec` с обработкой `on_exit`
- Добавить периодическую очистку мёртвых процессов

---

### 2.4 Модуль AI: Синглтон с глобальным состоянием
**Файл:** `backend/services/ai_assistant.py:30-33`
```python
def __new__(cls):
    if cls._instance is None:
        cls._instance = super().__new__(cls)
    return cls._instance
```
**Проблема:** Синглтон хранит модель в памяти. При повторных запросах к `/ai/chat` создаётся новый `LocalAssistant` (фактически тот же объект), но модель уже загружена. Проблема в том, что Llama модель занимает 2-8 ГБ RAM и не освобождается.

**Риск:** Модель загружается при первом запросе и остаётся в памяти навсегда. Нет механизма graceful shutdown для освобождения памяти.

**Рекомендация:**
- Добавить метод `unload_model()` для освобождения памяти
- Добавить timeout для автоматической разгрузки модели
- Добавить метрики использования (память, время отклика)

## 3. Проблемы безопасности

### 3.1 Отсутствие аутентификации API
**Проблема:** Все эндпоинты API не требуют аутентификации. Любой процесс на машине может:
- Получить профиль пользователя
- Запустить Minecraft от имени пользователя
- Удалить инстансы
- Изменить настройки

**Риск:** Если запустить backend на 0.0.0.0, любой в сети получит доступ.

**Рекомендация:** Добавить API key или JWT для всех эндпоинтов, кроме `/health` и `/ping`.

---

### 3.2 Отсутствие rate limiting
**Файл:** `backend/main.py`
**Проблема:** Нет ограничений на количество запросов. Злоумышленник может:
- Перебирать пароли (если будет добавлена авторизация)
- DDoS API
- Загружать сервер запросами к Modrinth через backend

**Рекомендация:** Добавить `slowapi` или аналог для rate limiting.

---

### 3.3 Валидация путей (Path Traversal)
**Файл:** `backend/api/v1/instances.py:82-94`
```python
async def get_instance(name: str):  # ❌ Без валидации имени
    instance = Instance.load(name)
```
**Проблема:** Имя инстанса используется как путь к файлу без санитизации. Злоумышленник может передать `../../../etc/passwd` (на Linux) или `..\\..\\windows\\system32` (на Windows).

**Риск:** Чтение/запись произвольных файлов на системе.

**Рекомендация:** Валидировать имя инстанса: только `[a-zA-Z0-9_-]`.

---

### 3.4 Валидация файлов при импорте
**Файл:** `backend/api/v1/instances.py:181-202`
```python
@router.post("/instances/import")
async def import_instance(request: ImportInstanceRequest):
    path = Path(request.file_path)  # ❌ Путь из запроса клиента
```
**Проблема:** Клиент передаёт путь к файлу, который сервер читает напрямую. Злоумышленник может указать путь к системному файлу.

**Риск:** Чтение произвольных файлов на сервере.

**Рекомендация:** Принимать файл как multipart/form-data, а не путь.

---

### 3.5 Subprocess injection
**Файл:** `backend/core/minecraft.py:190-196`
```python
process = subprocess.Popen(
    command,  # ❌ command формируется из внешних данных
    cwd=str(self.minecraft_dir),
    stdout=err_file,
    creationflags=subprocess.CREATE_NEW_CONSOLE if os.name == 'nt' else 0
)
```
**Проблема:** Команда формируется из `minecraft_launcher_lib`, но при неправильной версии/конфигурации может привести к инъекции команд.

**Риск:** Выполнение произвольных команд (хотя и ограничено через список аргументов).

## 4. Проблемы производительности

### 4.1 Создание ClientSession на каждый запрос
**Файл:** `frontend/services/api_client.py:27-31`
```python
async def get(self, endpoint, params=None, **kwargs):
    async with aiohttp.ClientSession(timeout=_DEFAULT_TIMEOUT) as session:  # ❌ Новый session на каждый запрос
        async with session.get(url, params=params, **kwargs) as resp:
            return await resp.json()
```
**Проблема:** Каждый HTTP-запрос создаёт новый `ClientSession`, что означает:
- Новый TCP handshake
- Новый DNS запрос
- Нет connection pooling

**Риск:** Медленная работа, избыточная нагрузка на сеть.

**Рекомендация:** Создать один `ClientSession` на время работы приложения и переиспользовать его.

---

### 4.2 Синхронные операции в async контексте
**Файл:** `backend/api/v1/minecraft.py:90`
```python
await asyncio.get_event_loop().run_in_executor(None, mc.install_version, request.version_id)
```

**Проблема:** Синхронные операции запускаются через `run_in_executor`. Это правильно, но в нескольких местах (install_forge, install_fabric) код дублируется.

**Рекомендация:** Вынести в отдельную утилиту.

---

### 4.3 Чтение всех Java установок при каждом запросе

```python
@router.get("/settings/java/", response_model=list[JavaInfo])
```

**Риск:** Запросы к `/settings/java/` занимают секунды.

**Рекомендация:** Кэшировать результат с инвалидацией (например, при изменении переменных окружения).

### 4.4 Отсутствует кэширование Modrinth API

## 6. Проблемы frontend (PyQt6)

### 6.1 Создание event loop в потоках
**Файл:** `frontend/pages/*.py` (повсюду)
```python
def run(self):
    import asyncio
    result = asyncio.run(self.api.list())  # ❌ Новый event loop в каждом worker
```
**Проблема:** PyQt не имеет встроенного async support. Использование `asyncio.run()` в `QThread` — это hack, который:
- Создаёт новый event loop для каждого worker
- Не может работать с вложенными async вызовами
- Не может использовать Qt signals внутри async кода

**Риск:** Утечки ресурсов, непредсказуемое поведение при высокой нагрузке.

**Рекомендация:** Использовать `QNetworkAccessManager` вместо aiohttp для HTTP запросов.

---

### 6.2 Утечка виджетов при удалении
**Файл:** `frontend/pages/home_page.py:136-139`
```python
while self.instances_layout.count():
    item = self.instances_layout.takeAt(0)
    if item.widget():
        item.widget().deleteLater()
```
**Проблема:** `deleteLater()` планирует удаление, но виджет может оставаться в памяти до следующего события Qt.

**Риск:** При частой перерисовке — накопление мёртвых виджетов.

**Рекомендация:** Использовать `item.widget().setParent(None)` + `del item.widget()` для немедленного удаления.

**Рекомендация:** Добавить `QProgressBar` или `QMovie` (спиннер) при загрузке данных.

### 7.5 WebSocket без heartbeat
**Файл:** `backend/api/v1/ai.py:34-82`
